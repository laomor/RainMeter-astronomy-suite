## 这四个视图到底能看啥？

| 视图 | 一句话说清楚 | 能解决你啥好奇 |
|---|---|---|
| **Globe** | 用 360 张地球图跟着时间走，让图转起来 | 想看“现在地球哪一块被照亮了” |
| **Trajectory Viewer** | 画出太阳和月亮每天东升西落的轨迹 | 想看“今天这俩是怎么爬坡又怎么下坡的” |
| **Event Tracker** | 把未来几次的升降时间点排出来 | 想看“接下来几次日出日落、月出月落都在啥时候” |
| **Position Simulator** | 专门算好当前的周期，展示天体在天空的相对位置 | 想看“太阳/月亮现在到底飞在天空的哪一块” |

这四个视图其实共用一个数据源，只是我用了不同的算法去“画”它们。

## 部署前，先看懂这玩意是怎么跑起来的？

其实整个项目就分两步：**去网上“进货”（采数据）**，然后**把货摆上货架（画皮肤）**。

```text
Windows 任务计划（AstronomicalEvents.xml）
        │  每 4 小时自动跑一次，开机也会补跑
        ▼
PowerShell 采集脚本（AstronomicalEvents.ps1）
        │  拿着 API 密钥去和风天气、百度地图要数据
        ▼
4 个文本文件（存在 C:\Users\Public\Documents\Rainmeter Data\）
        │
        ├─ 前两个是给人看的：yyyyMMddHHmm + 事件名
        └─ 后两个是给机器算的：Unix 时间戳 + 事件名
        │
        ▼
Rainmeter 皮肤（Lua 算数 + INI 贴图）
        │  Lua 读时间戳文件，算出“现在该用第几张图”和“现在该在哪个坐标”
        │  INI 把图和字摆到你的桌面上
        ▼
你屏幕上看到的各种视图
```

一句话：**PS1 负责去网上抓时间，Lua 负责把这些时间翻译成图片序号和坐标，INI 负责把它们画出来。**

## 快速部署（保姆级教程）

### 第一步：建个文件夹
1. 右下角找到 Rainmeter 的雨滴图标，右键 → **“皮肤” → “打开皮肤目录”**。
2. 在 `Skins` 文件夹里，新建个名叫 **`Astronomy Suite`** 的文件夹。

### 第二步：把文件对号入座
从仓库下载文件，按这个结构塞进去。*(注意：`@Resources` 是个公共资源库，所有皮肤都会去这里找图片和脚本)*

```text
Rainmeter/Skins/Astronomy Suite/
│
├── @Resources/                     # 公共资源
│   ├── globe/                      # 把 GlobePicture.zip 解压到这里
│   │   └── ... (直到 globe_359.png)
│   ├── Background_double.png       # 从 Background/ 拿
│   ├── Tracker_*.png               # 从 icon/ 拿
│   ├── Globe.lua 等 5 个脚本       # 从对应的 Script_ 文件夹拿
│
├── Globe/                          # 地球光照球皮肤
│   └── 相关的 ini 文件和 BodyType.inc
│
└── SunMoonTracker/                 # 轨迹与事件皮肤
    └── 相关的 ini 文件
```

### 第三步：搞点数据来
皮肤是个空壳，得给它喂 `C:\Users\Public\Documents\Rainmeter Data\` 目录下的 txt 文件。两条路：

**路子 A：只想看看效果（极速版）**
直接去仓库的 `Event Time Case` 文件夹，把里面的 4 个 `.txt` 扔进上面的目录里。（里面默认是北京的数据，够你跑起来看了）。

**路子 B：想长期自己用（折腾版）**
1. 把 `Users Public Documents` 里的 `AstronomicalEvents.ps1` 和 `WeatherApiKeys.json` 放到 `C:\Users\Public\Documents\`（这俩必须在一块）。
2. 去 [和风天气](https://id.qweather.com/#/login) 和 [百度地图](https://lbsyun.baidu.com/apiconsole/becomedev/selection) 白嫖两个免费 API Key 填进去。
3. 右键 `.ps1` 文件选“使用 PowerShell 运行”，看它能不能吐出数据。
4. 没问题的话，把 `AstronomicalEvents.xml` 导入系统的任务计划程序。以后每 4 小时它就会自动去进货。
   *(用 SYSTEM 账户跑，就是为了不管电脑当前谁登录、甚至锁屏了，它都能准点干活)*。

### 第四步：开玩！
刷新 Rainmeter，展开 `Astronomy Suite`，喜欢哪个点哪个。

## 核心原理与算法模型

这玩意到底怎么转的？其实全靠一个大杀器：**时间比例 `t`**，然后兵分两路去画图。

### 基础：算出一个时间比例 `t`
不管画啥，咱们首先得知道“现在”夹在哪两次事件中间。找到前后的 `prevEvent`（上一次）和 `nextEvent`（下一次），套公式：

```text
ratio = (now - prevEvent.time) / (nextEvent.time - prevEvent.time)

if (前一次是升起 AND 下一次是落下):  
    t = ratio        // 白天（可见），t 从 0 跑到 1
else:              
    t = 1 + ratio    // 黑夜（隐藏），t 从 1 跑到 2
```
> **通俗点说**：`t` 就是个进度条。白天从升到落是 0 到 1，晚上从落到升是 1 到 2。

有了这个进度条 `t`，两个不同的皮肤系列就各显神通了：

### 分支一：Globe（地球光照球）
这哥们比较单纯，它只要图片序号。拿着 `t` 去日出和日落的图片序号中间插值，算出一个 `0~359` 的编号，直接贴出来。
- 白天（`t ≤ 1`）就在日出和日落的图里找。
- 夜里（`t > 1`）就在日落和第二天日出的图里找。

> **晨昏线到底干嘛用的？** 360 张图里，晨线和昏线对应的两张图就是“本地日出”和“本地日落”的分界线。我把它们当成了**边界锚点**，把图分成了白天和黑夜两个区间。
*(注：月亮球借用了同一套纹理和公式，只是用月出月落来驱动。)*

### 分支二：SunMoonTracker（三个视图）

这系列要算完整的 `(X, Y)` 坐标。记住口诀：**Y 轴靠 `t` 算，X 轴靠绝对时间或周期算。**

**1. Y 轴：抛物线模型**
白天用开口向下的抛物线，晚上用开口向上的：
```text
y = HorizonY - (HorizonY - apex) * (1 - (2t - 1)²)
```
效果就是：升/落的时候在地平线，到中间（`t=0.5`）飞到顶点，半夜（`t=1.5`）沉到底点。太阳的顶点高度会根据白天时长动态变（夏天高，冬天低）；月亮我偷懒了，固定高度没做动态。

**2. X 轴：八仙过海，各显神通**
- **Trajectory Viewer**：`x = 起点 + (现在 - 今天零点) / 每像素秒数`。把一整天硬塞进时间轴里，零点重置。
- **Event Tracker**：算个时间窗口，把当前时间固定在左边一点，然后把事件一个接一个往后排。
- **Position Simulator**：这个最特殊，非要找齐“四个事件”拼成一个完整周期，再把当前时间映射到整条轴上。
  > **重点说说：为什么非得找四个事件？**
  > 因为天体有四个阶段：不可见上升、可见上升、可见下降、不可见下降。
  > 如果只看前后两个事件，遇到某些时间点（比如晚上 22 点，此时太阳最低点在次日 0:20 左右），系统可能会直接把次日 0:20 当成 X 轴的新起点。这下坏了，根据当前时间算出来的坐标会跑到极左端，图标直接“飞出屏幕”。
  > 所以必须找齐四个事件把周期拼完整，确认当前到底处在哪一段（把 22 点正确塞进周期的后半段），才能定好起止点。

## 移植避坑指南（过来人的血泪）

如果大佬想把这套逻辑搬到 Web 或者 App 里，这几条建议一定要看：

### 1. 关于 API 防扣费
- **别把开发者的 Key 当大怨种**：如果你做给别人用，千万别把 Key 写死在代码里。给用户留个填自己 Key 的设置接口。
- **少请求就是省钱**：建议一次性把数据拉多点（比如一周），让用户本地缓存慢慢用，别每次打开都去请求，不然很容易触发计费。

### 2. 渲染升维（摆脱 360 张图）
- **现在的土办法**：我现在用的 360 张图，默认太阳直射赤道，没去模拟南北回归线，极昼极夜根本看不出来。
- **高级玩法**：换到 Web/App 上，直接上 Three.js 或者原生 3D 引擎。搞一张地球皮贴上去，用 Shader 结合太阳直射的经纬度算，什么季节、什么纬度都给你算得明明白白。

### 3. 画曲线，别死磕抛物线
- **为啥用抛物线？** 不是因为 Rainmeter 画不出曲线，而是我在画的时候，数据这块做不出来，没法很好地呈现那条平滑曲线，最后只能折中选了这个算法。
- **换个好用的工具**：你用 Web 的话，直接 SVG、Canvas 或正弦函数，甚至用专业的太阳高度角算法来画，画出来的轨迹绝对比我现在顺滑得多。

### 4. 别被月亮“坑”了
- **月亮偶尔会旷工**：它公转周期大概 24 小时 50 分，所以每个月总有那么两天，它只有升起或只有落下的数据。你直接抓原始数据，可能长这样（时间错乱，中间还有空的）：
  ```text
  202610291937Moonrise
  202610291018Moonset
  202610302044Moonrise
  202610301124Moonset
  202610312156Moonrise
  202610311219Moonset
  202611012310Moonrise
  202611011304Moonset
  Moonrise
  202611021340Moonset
  202611030021Moonrise
  202611031410Moonset
  202611040129Moonrise
  202611041437Moonset
  ```
- **我在后台把它擦了屁股**：我在 PS1 里遇到空数据就打 `null` 标记，用时间排序把垃圾数据踢到最后，再切掉头尾。
- **前端留个心眼**：只要后端数据干净，前端稍微做个 `tonumber` 判断防止别人改坏文件就行了。千万别学我偷懒，如果你数据层没洗干净，前端一定要写容错！
